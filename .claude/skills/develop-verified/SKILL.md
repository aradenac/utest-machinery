4. It audits approved scope against the true merge-base-to-head diff, unnecessary abstractions, redundant tests and stalled progress from existing evidence; it does NOT run full pytest/Docker/build suites. It returns grounded minimal actions rather than edits. The lead tests/refutes findings; do not rubber-stamp or let the guardian create requirements. Do not spawn a continuously polling guardian. If the SAME defect class causes material regressions after TWO distinct correction strategies, STOP further local patch/re-review iterations on that class. Compare the root invariant and a simpler architectural alternative, including an honest explicit unsupported-case limitation where allowed by the approved contract. If a bounded strategy cannot be justified, report BLOCKED and request owner arbitration; never paper over known mandatory defects or silently drop acceptance requirements. A new guardian report is advisory and must not itself spawn another reviewer/qualification cycle. If an unchanged finding recurs without new evidence, report its status rather than re-probing. Aim for minimum justified DIFF, not minimum lines or omitted necessary tests/docs.
