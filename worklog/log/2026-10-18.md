## What was done

Implementation (host CLI, `mtm/`):

- `cscan.py` — deterministic C scanner (comment/string stripping, definitions, calls,
  prototypes). Fixed two scanner bugs: a definition split across lines was missed
  (`_DEF_RE` needs `[ \t\r\n]*{`), and a return type spelled `int`/`void` was wrongly
  filtered as a control keyword (`_CONTROL_KEYWORDS`).
- `inventory.py` — `Requirement`/`Unit`/`Inventory`, `build_inventory`, requirement
  extraction (verbatim + line anchors), content-addressed `snapshot_hash`.
- `ccompile.py` — `HostCompiler` (`-fsyntax-only`, link, run) used by feasibility and smoke.
- `feasibility.py` — READY / ADAPTED / BLOCKED, justified by compilation and external calls.
- `llm.py` — `MockProvider` (recorded responses, offline/token-free) and
  `ClaudeCodeProvider` (runs the in-image harness with a scoped `--env-file`; the bench is
  **not** mounted). `PROMPT_VERSION` bumped `plan-v1` → `plan-v2` with the template change.
- `plan.py` — prompt built from the deterministic inventory only; `parse_plan` **grounds**
  the model's JSON: a `SPECIFIED` oracle citing no existing requirement is downgraded to
  `UNDETERMINED`, unknown functions/requirements are rejected, and expected values are
  stripped from `UNDETERMINED` scenarios.
- `gen.py` — deterministic Unity generation from the reviewed plan: private shims, mocks,
  one test file per unit, a runner and a manifest. The model never writes C.
- `generate.py` — orchestrator writing `state/generate/{inventory,feasibility,plan,suite,smoke}.json`;
  status SUCCEEDED / FINDINGS(10) / BLOCKED(20) / TOOL_FAILURE(30).
- `cli.py` / `commands.py` — `generate` (`--provider auto|mock|claude-code`, `--model`,
  `--dry-run`) and read-only `plan`.
- `mtm/vendor/unity/` — Unity 2.6.0 core (MIT). `mtm/recordings/*.json` — five recorded
  responses. `mtm/image/{mtm-llm.sh,ccr-config.template.json}` — the in-image harness.

Defects found and fixed while making the **real** model path work (each produced a genuine
wrong result, not a cosmetic issue):

1. `_emit_test_file` declared `out0` once per **case** in one function scope → redeclaration.
   Fixed with per-case names (`out<case>_<index>`).
2. The mock call counter was reset once per **test**, but `expect_calls` is per **case** →
   later cases inherited the previous count and reported a false defect. Fixed: reset inside
   the case loop.
3. A pointer argument was initialised to `0` instead of the planned initial pointed-to value
   → recovery/preserve tests asserted against the wrong starting state. Fixed: the case's
   `args` value for a pointer parameter is its initial value.
4. A control key the generator does not implement (`sequence`, `call_count`) was silently
   ignored, leaving the mock at its default → a **fabricated** implementation defect. Fixed:
   `_case_problem` refuses the scenario and records a **limitation**; `generate` reports such
   a suite as FINDINGS, never SUCCEEDED.
5. A scalar supplied for an aggregate (struct) pointee generated C that did not compile.
   Fixed: `aggregate_aliases` detects struct/union/array typedefs; such a case requires
   `{"expr": "..."}` or is refused with a limitation. The prompt now states this contract.
6. Model declarations carried a C **comment** around the signature → parse failure / would be
   emitted verbatim. Fixed: `_strip_c_comments`.

Harness defect found end-to-end: as an *agent* the model answered with prose ("why I am
stopping…, say so and I'll write the unit…") instead of JSON. Fixed with
`--tools "" --strict-mcp-config --append-system-prompt-file` (a pure text completion; see
decision [0011](../decisions/0011-llm-harness-pure-completion.md)). Also: the container now
runs as the invoking user, so the loopback key helper is baked into the image (Dockerfile)
instead of written at runtime into `/usr/local/bin`.

## Extra defect found during the review pass (fixed)

While stressing the runner I found a real under-count: **Ceedling builds and runs one
executable per test file**, so a multi-unit scope prints several per-file Unity summaries and
**no grand total**. `ceedling._unity_summary` used `re.search` (first match only), so a
two-unit bench reported only the first file's totals — a second file's failures could be
masked. Reproduced by adding a second unit+test to the probe project (two summaries:
`2 Tests 1 Failures` then `3 Tests 0 Failures`). Fixed to sum every summary; regression test
`test_unity_summary_aggregates_every_test_executable`. Also confirmed Ceedling compiles only
what each test needs, so an unrelated non-compiling source does not break a test that does not
include it (relevant to B3's "exclude the blocked unit" posture — belt and braces).

A second, related gap: if Unity's summary **counts** failures but no `:FAIL` line is parseable
(an unexpected format), the run would have fallen through to SUCCEEDED. Fixed: a counted
failure with no parsed detail is still recorded as an `IMPLEMENTATION_DEFECT` finding
(`test_counted_failure_with_unparseable_detail_is_still_a_finding`). Also verified a stale
image with **no Ceedling** yields `TOOL_FAILURE` (30), not success.

## Independent pre-PR contract review (AP-01/AP-03 supplement) and its fixes

Per the new instruction on `main` (commit `daf8eca`, `/verify-feature`), ran an **independent
`contract-reviewer`** pass over the branch before declaring readiness. Verdict
`CHANGES_REQUIRED`, three grounded findings — all reproduced and fixed:

1. **[high] basename collision.** Two selected units sharing a basename
   (`alpha/sensor.c` + `beta/sensor.c`, both READY) silently overwrote each other in the flat
   revision: `src/` held one file, one test was emitted, yet `test_functions` and
   `status=SUCCEEDED` reflected both — a silent loss of a unit's suite with an inflated count.
   Fixed: colliding units are refused with a recorded limitation (a flat C revision cannot
   disambiguate `#include "x.h"`), generalized to also refuse a unit whose local header include
   names a colliding file; the never-read `blocked_headers` helper is removed.
   Regression `test_two_units_sharing_a_basename_are_refused_not_silently_overwritten`.
2. **[medium] oracle mis-mapping.** `_scenario_for_test` reverse-split the test name
   (`split("_")[-1]`), so an id with `-`/`_` (e.g. `S1_boundary`) mapped to a truncated id and
   an **empty** oracle statement — breaking the milestone's own "test-to-SDD link" criterion.
   Fixed: `test_name_for()` is the single naming rule; `_findings` and `cmd_plan` resolve
   through the plan's `(unit_id, scenario_id) → name` map instead of parsing the name.
   Regression `test_finding_maps_back_to_its_oracle_for_ids_with_dashes_and_underscores`.
3. **[medium] stale derived artefacts.** BLOCKED / dry-run early exits wrote only
   `inventory.json`/`feasibility.json`, so a previous input set's `plan.json` remained and
   `mtm plan` presented it as current (with a snapshot that no longer matched the inventory).
   Fixed: `run_generate` clears the derived artefacts on every run, and `cmd_plan` refuses a
   plan whose snapshot no longer matches the inventory (`SNAPSHOT_MISMATCH`, exit 40).
   Regressions `test_an_early_exit_clears_the_previous_plans_derived_artifacts`,
   `test_plan_refuses_a_stale_plan_whose_snapshot_no_longer_matches`.

Verified after the fixes: the finding→oracle link resolves correctly offline and on the live
route (saturation → `S1`/`S3` with their SAT statements).
