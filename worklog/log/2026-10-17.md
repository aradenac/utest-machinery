## D6 — what the user must provide (explained)

In plain terms, for the in-image Claude Code + CCR to route to `deepseek-v4.1-flash` exactly
like the host does, I need **four non-secret pieces of information** about the working host
route (never the token itself), because the host stores its CCR config in `config.sqlite`
rather than a readable `config.json`:

1. **The provider/route name and type** the host uses (e.g. a custom OpenAI-compatible
   provider pointing at the Scaleway gateway), as it appears in the router UI/config.
2. **The exact upstream base URL** shape the container should call. The host uses
   `SCW_BASE_URL`; I need to know whether the container should use the **same** URL (i.e.
   whether it is reachable from inside Docker) or an internal alias.
3. **The exact model identifier** the router sends upstream (`deepseek-v4.1-flash` — confirm
   spelling) and the **API surface** (OpenAI `/chat/completions` vs Anthropic `/v1/messages`).
4. **Any non-secret headers/prefixes** the gateway expects (e.g. an API-key header name or a
   path prefix), if different from the defaults.

No secret is needed in the explanation: the token comes from
`~/.config/utest-machinery/credentials.env` (or a runtime secret mount) at execution time and
is never copied into the image, Git or logs.

## D6 — RESOLVED via option B (read the config schema)

With the user's go-ahead, read `~/.claude-code-router/config.sqlite` **read-only**, masking
every value whose key contains key/token/secret/auth/password/bearer/api and any long string.
Schema: 6 objects (`api_keys`, `app_config`, `config_schema_migrations`,
`legacy_storage_backups`, `legacy_storage_cleanup`, `runtime_state`).

**Derived route (nonsecret):** provider `scaleway`, type `openai_chat_completions`, base
`https://llm.tools.lacroix-dev.com` (chat endpoint `/chat/completions`), model
`deepseek-v4.1-flash`, gateway `127.0.0.1:3456`, Claude profile `default-claude-code` with
all model slots on `scaleway/deepseek-v4.1-flash` plus four `CLAUDE_CODE_*` env vars.

**Security finding:** the provider api_key is stored inline in the SQLite and is **byte-equal
to `SCW_BEARER_TOKEN`**. Confirms the host config must never be copied into the image; only
the route shape is transferred, the token injected at runtime.
→ [`decisions/0004-in-image-llm-route.md`](../decisions/0004-in-image-llm-route.md).

**Second pass — agent-profile layer (user prompt):** the user flagged that the agent profile
(context sizing) matters. Captured the distinct layer at
`profiles/default-claude-code/claude/settings.json`: `ANTHROPIC_BASE_URL` and siblings
`http://127.0.0.1:3456`; all `ANTHROPIC_DEFAULT_*_MODEL` = `scaleway/deepseek-v4.1-flash`;
sizing `CLAUDE_CODE_MAX_CONTEXT_TOKENS=256000`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW=240000`,
`CLAUDE_CODE_MAX_OUTPUT_TOKENS=16384`; `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`;
`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`; `NO_PROXY=127.0.0.1,localhost,::1`. The key is
supplied by `apiKeyHelper` (the CCR wrapper script), **not** embedded. The `autoMode`
allow/soft_deny lists are **dev-host agent policy, not product behavior** and are not copied.
Decision 0004 updated to require **both layers** in the sanitized template.

## Session 1 (continued 2) — permissions granted: Dagu gate proven

The user granted broader permissions and relaunched. Executed the Dagu gate proof (isolated
`DAGU_HOME=/tmp/dagu-gate/home`, repo untouched):

- Downloaded `dagu-org/dagu` `v2.20.1`, **sha256 verified** against upstream `checksums.txt`
  (`0d5c1612…49837`); `dagu version` = `2.20.1`; bundled `LICENSE` = GPL-3.0.
- Gate items 1,2,5,6,7 **PASS**; item 4 **PASS** (state entirely under `DAGU_HOME`, per-run
  `status.jsonl` + `dag.json`, `history --format json`).
- **Limitation found (item 3):** after a SIGKILL of the Dagu process, the run stays reported
  `running`/`FRESH` forever — Dagu does **not** reconcile a dead owner on the local backend.
  The mtm wrapper must map a `running` run whose PID is dead to **`INTERRUPTED`** and never
  report it as RUNNING or success (per `workflow-failures.md`).
- Other measured facts: DAG files passed by path must **not** define `name:` (validate
  rejects); `--run-id` gives deterministic IDs; `retry --run-id` reuses the same ID and exits
  `1` on repeat failure; unset `auth.mode` warns each call (use `none` headless).
→ [`decisions/0005-dagu-gate-proof.md`](../decisions/0005-dagu-gate-proof.md). D3 closed.
