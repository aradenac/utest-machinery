**TC-1 (MANDATORY, I5 regression) — enum parameters blanket-refused.**
`mtm/gen.py::_chart_type_map` sets `aggregate = bool(fact.record) or fact.opaque`,
and clang reports `record = {"kind":"ENUM"}` for an enum alias. An **enum is a
scalar C type** (`e_t x = (e_t)7;` compiles), and the retired scanner chased only
`struct`/`union`. So the candidate refuses every enum-typed parameter / `enum *`
out-param as "an aggregate type":

| Revision | `sensor_status_t` (enum) alias | Outcome |
| --- | --- | --- |
| base `755d27e` | `aggregate=False` | generates, `case_problem=None` |
| candidate `5cf92a5` | `aggregate=True` | **refused** ("argument 0 points at an aggregate type") |

The blind spot: the re-expressed §C tests cover enum *alias sharing*, never an enum
**parameter** — so neither the offline suite nor the docker tier caught it. This is
exactly why the early challenge was scheduled: it hit a class the green suite could
not.

**Disposition:** ACCEPTED; corrective lot `utm-u8x.3` (P0) dispatched on the same
worktree (fix the `record`→`aggregate` boundary; audit consumers; add the missing
enum-parameter regressions + an in-image compile+run). Convergence call recorded in
Beads: **CONTINUE** — a distinct bounded defect (over-broad mapping), not a repeat of
the escalated guard-class, so no REPLAN.
