## Acceptance contract (finite)

Invariant 1 — **offline replay truthfulness.** `mtm verify` rebuilds+runs the
frozen bench with no LLM and no edit to selected sources/tests/oracles; a changed
input snapshot yields `STALE_INPUT`, never a misleading replay; a tool fault is
never reported as a functional pass or a functional failure.

Invariant 2 — **profile truthfulness.** Each profile reports `SUPPORTED` or a
concrete non-applicability/tool limit with its native reports, flags and
denominators; no invented 100 % or target-MCU claim.

Invariant 3 — **generator fidelity.** Every emitted pointer argument has exactly
the declared indirection depth, the post-call observable is read through the
argument the callee received (not a stale backing local), and a shape the
generator cannot render faithfully is a **named limitation**, never a fabricated
`PASS`, an unjustified pointer cast or a false `IMPLEMENTATION_DEFECT`.

Invariant 4 — **R04.** A semantically false expectation that cites a *valid*
requirement id is detected as `CONTRADICTED_BY_SDD`; an ambiguous/absent expected
value stays `INDETERMINATE`; an unsupported oracle never substantiates a
conformity verdict or a code-defect claim.

Invariant 5 — **R22.** The *same unchanged* frozen tests/oracles, run on
separately snapshotted correct/faulty inputs through the offline path, classify
each seeded defect `DETECTED/MISSED/FALSE_POSITIVE/NOT_EVALUABLE` against
withheld ground truth; a compile error or tool crash is never "detection").

## Early test-challenger review — three CONFIRMED MANDATORY defects fixed (session 4)

The early `test-challenger` (fresh isolated context, read-only) challenged the C
generator on the frozen `dd122e7`. It reported **three CONFIRMED MANDATORY**
defects, all in §A/§C scope; the lead independently reproduced each on the
current tree and **ACCEPTED all three** (no reviewer authority to overrule the
reproduction):

* **F1 — array/function-pointer `typedef` silently accepted.** `cscan.scan_typedefs`
  extracted the alias name with `([A-Za-z_]\w*)\s*$`, which returns `None` for
  `typedef int Arr[4]` / `typedef void (*CB)(int)` (the declarator ends in `]`/`)`),
  so the `opaque` marker was **never recorded** and `_unsupported_param_shape`'s
  opaque refusal was dead code. Reproduced end to end: `limitations == []` and an
  emitted `first((Arr)5);` — `gcc -std=c99 -Werror` → `error: cast specifies array
  type`, exit 1 (an opaque `TOOL_FAILURE`, the exact class §A/§C forbid).
  **Fix:** match the alias position explicitly (`_FNPTR_ALIAS_RE` / `_ARRAY_ALIAS_RE`)
  when the declarator is opaque, so the alias is recorded and refused with a named
  limitation. Probed: `Arr`/`CB` refused, plain `scalar_t`/`mode_t` unaffected.
* **F2 — mocked dependency through a pointer `typedef` at the wrong depth.** The
  mock path called `split_declaration`/`mock_controls` with no typedef map, so
  `typedef int *P; void dep_write(P *pp);` (real `int **`) reported `out_depth 1`
  and emitted an uncompilable `P v = (P)5;` plus a `ReturnThruPtr` writing 4 bytes
  into the mock's pointer object (an unjustified pointer cast). **Fix:** thread the
  resolved `typedefs` through `split_declaration` → `mock_controls` at the real call
  site; the depth is now 2, so `_case_problem` refuses the multi-level write-through
  with its named limitation. Probed: `out_depth == {'pp': 2}`, scenario refused.
* **F3 — private CMock interface header lacks the alias definition.** The header was
  emitted as `#include <stdint.h>` + the raw declaration, so `void dep_write(P p);`
  compiled standalone with `unknown type name 'P'` (also for a plain alias like
  `vendor_adc_sample_t`) and *every* scenario mocking the symbol died as an opaque
  build failure. **Fix:** `cscan.typedef_statement_map` extracts the verbatim
  `typedef` statement for each alias; the interface header now prepends the aliases
  its declaration references (transitively, to a fixpoint). Probed: header carries
  `typedef int *P;` and compiles alone under `-Werror` (exit 0).

Challenger's explicit **non-findings** (confirmed, not acted on): the nested alias
chain `typedef int *P; typedef P *Q; Q qq` is already faithful; `const P *p` /
`P * const p` resolve consistently. Regression tests added:
`test_an_array_or_function_pointer_typedef_parameter_is_a_named_limitation`,
`test_a_mocked_dependency_through_a_pointer_typedef_is_refused`,
`test_a_mocked_dependency_using_a_typedef_is_declared_in_its_interface_header`
(the last compiles the header for real). These failures pre-fix (F1 emits an
uncompilable cast; F2 depth 1; F3 header without the alias).

**Note:** this invalidates the earlier "all green" fingerprint — the fixes are a
material code change, so the applicable tests and the independent final review are
re-run on the new candidate before publication.




## Session 5 — F3 third strategy (include-based alias sharing) and the guard-less aggregate limit

The F3 fix above (verbatim alias text prepended to the private CMock interface
header) was itself corrected after **two distinct strategies failed on the same
defect class** ("each TU must see each type alias exactly once" — the skill's
"two failed strategies" escalation):

1. **Verbatim from all sources** re-declared an alias the included shim already
   defines → duplicate definition; the `vendor-adapter` docker fixture exited 30
   (`test_adapted_unit_with_absent_header_is_built_from_a_private_shim`).
2. **Verbatim from copied sources only** still conflicts when the alias is an
   **anonymous aggregate** the unit header also defines: `typedef struct { int v; }
   S;` twice names two *different* anonymous types → gcc `error: conflicting types
   for 'S'` under `-Werror`. Mechanically confirmed in `/tmp/ty`: a duplicate
   *scalar/pointer* typedef compiles clean; a duplicate *anonymous-aggregate*
   typedef does not. This is **REGRESSION 2**.

**Strategy 3 (accepted):** the interface header now **`#include`s the copied
header that defines a referenced alias** instead of re-declaring it (one guarded
definition per TU); verbatim text remains only for an alias with no includable
header (defined in a `.c`). New helpers `_decl_alias_tokens` (shared transitive
walk) and `_header_has_guard`.

**Verified end-to-end in the product image** (`utest-machinery/mtm:1.0.0`), not
just by string equality:
* mocked dependency through a pointer typedef (`void dep_write(P p)`) — compile,
  link, run, `PASS`;
* mocked dependency through an anonymous-aggregate alias (`void dep_send(S *s)`) —
  `PASS` (the regression that motivated strategy 3);
* **two** mocked symbols sharing one defining header — no duplicate mock, `PASS`;
* guard-less header with a **scalar** alias — still `PASS` (no regression).

**New pre-existing limit found and named:** a guard-less header that defines an
*anonymous-aggregate* alias cannot be shared (the test includes it directly and via
the interface header; the repeat conflicts). It previously failed identically
(verified by stashing `gen.py` and re-running) as an **opaque `TOOL_FAILURE` with
`limitations == []`**. Plan §C requires a recorded limit, so the mock scenarios are
now refused with a precise limitation (`refused_mocks`) and the scenarios are
skipped — no uncompilable C emitted. Test:
`test_a_guardless_aggregate_alias_header_is_a_named_limitation`.

**Evidence on the corrected candidate:** full non-docker suite green; full
docker tier green (16 tests). Regression tests updated/added in
`tests/test_pr2_runner.py` (four). Decision record `0015` updated with the
strategy history. This again invalidates the prior fingerprint; the one bounded
independent PRE_PR review is re-requested on this revision before publication.

### Session 6 — independent PRE_PR review finding F-A1 (enum alias) accepted and fixed

The one bounded independent PRE_PR `contract-reviewer` ran on the corrected
fingerprint (base `3cbfea6`, head `9a97c40`; `mtm/gen.py` sha256 `a6350667…`) and
returned **CHANGES_REQUIRED** with one **mandatory** finding, which the lead
independently reproduced and **ACCEPTED**:

**F-A1 — anonymous `enum` alias in an unguarded header → uncompilable C with
`limitations == []`.** `cscan._AGGREGATE_DEF_RE` matched only `struct|union`, so
`scan_typedefs` recorded nothing for `typedef enum { E_A, E_B } e_t;`. The
guard-less-header check therefore saw no inline-body alias, did not refuse, and
emitted an interface header that `#include`d the *unguarded* header; a TU including
both it and the unit header got `redeclaration of enumerator 'E_A'` /
`conflicting types for 'e_t'`. Same defect class the PR fixed for struct/union,
left open for the neighbouring `enum` shape (AP-01 "relevant neighbouring case").

*Reproduction (accepted):* guard-less `foo.h` with `typedef enum { E_A, E_B } e_t;`
and `void dep_send(e_t e);` → `generate_suite` returned
`test_functions=['test_…S1']`, `limitations == []`, header containing
`#include "foo.h"`; `gcc -Werror` of the include-order TU → `redeclaration of
enumerator`.

*Fix (DECISION):* replace the narrow `aggregate` predicate with
**`invariant: an alias whose defining statement has an inline `{…}` body cannot be
duplicated and must be guarded`** — derived from `typedef_statement_map` (already
recorded) as `alias_inline_body` (statement contains `{`). This covers anonymous
`struct`, `union` **and** `enum` uniformly (a tag reference `typedef struct Tag S;`
or a plain/pointer typedef duplicates legally and needs no guard, so it is
correctly excluded). The guard-less refusal message now names
struct/union/enum.

*Evidence after fix:* guard-less enum → refused named limitation, no header written;
**guarded enum → shared `#include`, compiles+links+PASS in the image**; guard-less
struct still refused; guard-less scalar still admitted; guarded anon-struct and
pointer-typedef e2e still PASS. Regression test
`test_a_guardless_enum_alias_header_is_a_named_limitation` (guard-less refuse +
guarded `-Werror` compile). Full non-docker suite green; full docker tier green
(16 tests).

*Reviewer non-findings confirmed (reused):* the KeyError fix, struct/union sharing
and guard-less refusal, no LLM inside `verify`, DoD-1 status precedence,
R04/R22 classification. Reviewer evidence gaps: it did not execute `mtm verify`
across real profiles or R04/R22 e2e (lead-owned executed evidence stands) and
reproduced the counterexample with host gcc, not the full in-image path — the lead
closed that gap (guarded-enum e2e in the image, above).

### Session 7 — second independent PRE_PR review: F-A2 (tag-reference regression) accepted and fixed

The fresh final PRE_PR reviewer ran on revision 3 (head `fa753d9`) and returned
**CHANGES_REQUIRED** with one **mandatory** new finding the lead reproduced and
**ACCEPTED**: the F-A1 fix *narrowed* the guard check and regressed a shape the
previous revision refused.

**F-A2 — guard-less header with an inline **tag-named** body.** F-A1 replaced the
`aggregate` predicate with `"{" in alias_statement`. But the two predicates are
**complementary**, not substitutes:
* `typedef struct { … } S;` (anonymous body): `aggregate=True`, alias-statement has `{`.
* `struct S { … }; typedef struct S S_t;` (tag reference): `aggregate=True`, alias
  statement has **no** `{` — the body lives in the *same header*.
So keying only on the alias statement dropped the tag-reference shape: a guard-less
header with `struct S {…}; typedef struct S S_t;` and `void dep_send(S_t s)` emitted
a test with `limitations == []` and an interface header `#include`ing the unguarded
header → `redefinition of 'struct S'` / `conflicting types for 'S_t'`.

*Reproduction (accepted):* host gcc of the generated include order → `redefinition
of 'struct S'`, rc 1. *Honesty note:* at the true base `dd122e7` this shape was
**also** broken (verified in a `dd122e7` worktree: `tests=['test_…']`,
`limitations == []`); it was caught at the intermediate `9a97c40` by the `aggregate`
predicate, so F-A1 narrowed it. It is now correct on the merits.

*Fix (DECISION — restated root invariant at the right level):* **"a header is
unsafe to include twice iff it *defines* a `struct`/`union`/`enum` with an inline
`{…}` body"** — a *header-level* property, not a property of the alias statement
(`_header_defines_inline_type`, comment/string-stripped). This covers anonymous and
tag-named bodies uniformly and still admits a header with only plain/pointer
typedefs. The guard check now refuses a mock whose alias comes from an unguarded
inline-defining header, naming the header.

*Evidence after fix:* guard-less tag-ref refused (named limitation, no header);
guard-less anon struct/union/enum refused; guard-less scalar admitted; guarded
tag-ref/anon-struct/anon-enum/pointer/chained all share, compile and **PASS in the
image**; two mocks one header PASS. Regression test
`test_a_guardless_header_with_an_inline_tag_body_is_a_named_limitation`. Full
non-docker suite green; full docker tier green (16 tests).

*Reviewer non-findings confirmed:* F-A1 general invariant (anon enum/struct/union,
chained, guarded sharing, scalar admitted); no LLM inside `verify`; DoD-1 status
precedence (`TOOL_FAILED` branches); R04/R22 disjoint classification.
